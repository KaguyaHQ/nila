# Nila design pass

Nila should feel like a product from Apple or Braun — beautiful and functional
in equal measure. Every element earns its place.

Premium comes from Latin _praemium_ — a reward. Something worth more than its
alternatives. In physical design (Braun, Leica, Apple), premium manifests as:

- **Nothing is filler.** A Braun clock has 3 controls and feels complete. It
  doesn't apologize for having 3 controls.
- **Organization comes from the design itself**, not from labels about the
  design. A well-organized bookshelf doesn't need signs saying "Fiction" and
  "Non-fiction" — the arrangement communicates it.
- **Things are what they are**, not dressed up as something else. A button that
  navigates looks like a link. A toggle looks like a toggle. A destructive
  action looks like a last resort.
- **Own the full experience.** If a flow starts somewhere, it should conclude
  there. Every handoff — to a new tab, an email client, an external service — is
  a moment the product stopped being present, leaving the user to manage state
  that isn't theirs to manage. That fracture is felt even when users can't name
  it. Before adding any out-of-product step, ask whether the same outcome can be
  achieved without breaking context.
- **Think from first principles.** Don't copy patterns blindly. Ask what the
  ideal experience is for this specific context, then build that. Letterboxd,
  Spotify, and Stripe are references, not templates.
- **Design for the common case.** The primary user flow should feel effortless.
  Rare actions (delete, edit) should never degrade the browsing experience —
  move them out of the way.
- **Controls should move toward what users want, not away from what they
  don't.** When the intent is positive, the action should be positive too.
  Making someone disable the opposite to reach their goal is cognition tax —
  paid silently, on every interaction.
- **Remove before adding.** If something doesn't clearly serve the user, take it
  out. An empty space is better than a noisy one. No placeholder buttons, no
  "just in case" UI.
- **Every pixel is intentional.** Spacing, alignment, color, and typography
  should feel considered, not default. If two elements look slightly off, fix it
  — users feel it even if they can't name it.
- **UI should be quiet until needed.** Hide complexity (character counts,
  destructive actions, secondary controls) until the moment it matters.
  Progressive disclosure over upfront clutter.
- **Form follows purpose.** The right size, density, and layout depends on what
  the user is doing. A search dropdown should be tight and scannable. A detail
  page should breathe. Match the UI to the task.
